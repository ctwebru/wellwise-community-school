# Health Compass

Ты — senior product designer и mobile UX/UI designer. Твоя задача — спроектировать готовый дизайн мобильного приложения для iOS/Android для личного проекта врача.

Важно: нужен не общий концепт, а именно продуманный, целостный, реалистичный дизайн MVP-приложения, который можно будет передать в разработку. Дизайн должен быть современным, чистым, спокойным, вызывать доверие, но не быть “больничным” или перегруженным медицинской стилистикой.

====================

1. ОБЩИЙ КОНТЕКСТ ПРОЕКТА

====================

Это B2C-приложение для пациентов одного врача.

Главная идея приложения:

- дать пользователям доступ к бесплатным постам;

- дать доступ по подписке к разделу “Школа здорового человека”;

- позволить пользователям читать посты, смотреть встроенные видео, ставить реакции, писать комментарии и сохранять материалы в избранное;

- показывать статус подписки;

- отправлять пользователя на оплату на внешний сайт;

- после оплаты возвращать пользователя в приложение и автоматически обновлять статус подписки.

Приложение должно выглядеть как полноценный мобильный продукт, а не как CRM, не как админка и не как корпоративная система.

Стиль интерфейса:

- доверительный;

- спокойный;

- экспертный;

- современный;

- чистый;

- минималистичный;

- с акцентом на комфортное чтение контента;

- с хорошей визуальной иерархией;

- без визуального шума.

Нужен mobile-first дизайн, ориентированный на реальные экраны смартфона.

====================

2. РОЛИ В ПРИЛОЖЕНИИ

====================

В приложении есть 3 роли:

1. Пользователь

- читает бесплатные посты;

- читает посты в разделе “Школа здорового человека” только при активной подписке;

- открывает отдельный экран поста;

- ставит реакции;

- пишет комментарии;

- добавляет посты в избранное;

- смотрит статус своей подписки;

- переходит на внешний сайт для оплаты;

- получает push-уведомления.

2. Модератор

- все возможности обычного пользователя;

- может модерировать комментарии.

3. Администратор

- все возможности модератора;

- создает посты прямо внутри мобильного приложения;

- редактирует посты;

- выбирает, в какой раздел публиковать пост: “Посты” или “Школа здорового человека”;

- может публиковать сразу;

- может отложить публикацию;

- может сохранять черновики.

Важно:

это одно приложение для всех ролей.

Не нужно делать отдельную админку.

Нужно предусмотреть role-based UI:

- обычный пользователь не видит административные функции;

- администратор видит дополнительные экраны и действия;

- модератор видит только доступные ему инструменты.

====================

3. ОСНОВНЫЕ РАЗДЕЛЫ ПРИЛОЖЕНИЯ

====================

Нужно спроектировать готовый дизайн следующих разделов.

1. Авторизация

Экран входа по email:

- ввод email;

- отправка одноразового кода;

- экран ввода кода;

- состояния ошибки;

- состояния загрузки;

- понятные тексты и дружелюбный UX.

2. Главный раздел “Посты”

Это бесплатная лента постов.

Здесь пользователь:

- видит список постов;

- открывает карточку поста;

- читает пост полностью;

- ставит реакцию;

- комментирует;

- добавляет в избранное.

Посты могут содержать:

- текст;

- эмодзи;

- фото;

- видео;

- форматирование текста.

3. Раздел “Школа здорового человека”

Это платный раздел с контентом по подписке.

Функционально посты здесь такие же, как и в бесплатной ленте:

- текст;

- фото;

- видео;

- форматирование;

- комментарии;

- реакции;

- избранное.

Но если подписка не активна:

- пользователь видит locked state / paywall;

- видит преимущества подписки;

- видит CTA на оплату;

- переходит на внешний сайт для оплаты.

Если подписка активна:

- пользователь видит контент без ограничений.

4. Экран отдельного поста

Нужно спроектировать экран полного просмотра поста:

- заголовок или начало поста;

- rich text контент;

- встроенные изображения;

- встроенное видео;

- блок реакций;

- блок комментариев;

- кнопка “в избранное”;

- удобный мобильный ритм чтения;

- хорошая читаемость длинного текста.

5. Комментарии

Нужно продумать UX комментариев:

- список комментариев;

- поле ввода;

- состояние пустого списка;

- возможность ответить;

- понятная структура обсуждения;

- действия модератора для модерирования комментариев.

6. Избранное

Экран, где пользователь видит сохраненные посты.

Нужно продумать:

- список избранного;

- пустое состояние;

- быстрый переход в пост.

7. Профиль пользователя

На MVP профиль очень простой.

Нужно включить:

- email пользователя;

- статус подписки;

- до какой даты активна подписка;

- доступ к избранному;

- выход из аккаунта;

- возможно краткий блок настроек уведомлений.

8. Экран подписки / paywall

Нужно сделать понятный и аккуратный экран:

- что дает подписка;

- чем отличается бесплатный доступ от платного;

- варианты тарифов: месяц, полгода, год;

- кнопка перехода к оплате на сайте;

- состояние “проверяем оплату”;

- состояние “подписка активна”.

9. Push / уведомления

Нужно предусмотреть UX для минимальных сценариев:

- новый пост опубликован;

- подписка скоро заканчивается.

Нужно продумать:

- как запросить разрешение на push;

- где это лучше показать;

- как ненавязчиво объяснить ценность уведомлений.

10. Административный контур внутри приложения

Для роли администратора нужно спроектировать UX следующих экранов:

- список постов;

- фильтры: черновики / запланированные / опубликованные;

- создание нового поста;

- редактирование поста;

- выбор раздела публикации: “Посты” или “Школа здорового человека”;

- настройка комментариев для поста;

- публикация сразу;

- отложенная публикация;

- сохранение черновика.

Важно:

UI создания поста должен быть простым, быстрым и нативным по ощущению.

Ориентир по ощущению — удобство публикации как в Telegram, но без копирования Telegram 1 в 1.

Не нужно делать сложный CMS-интерфейс.

Нужно сделать удобный мобильный composer.

====================

4. ФУНКЦИОНАЛЬНЫЕ ВОЗМОЖНОСТИ, КОТОРЫЕ ДОЛЖНЫ БЫТЬ УЧТЕНЫ В ДИЗАЙНЕ

====================

Нужно учесть в интерфейсе и состояниях следующие возможности:

- вход по email + одноразовый код;

- бесплатный и платный контент;

- статус подписки;

- переход на внешний сайт для оплаты;

- возврат в приложение после оплаты;

- автоматическое обновление subscription status;

- комментарии в обоих разделах;

- реакции;

- избранное;

- пуш-уведомления;

- роли и ограничения доступа;

- создание и редактирование постов администратором;

- отложенная публикация;

- список черновиков;

- модерация комментариев;

- best effort логика защищенного контента, где в платных разделах интерфейс должен выглядеть более защищенным и приватным.

====================

5. ПОЛЬЗОВАТЕЛЬСКИЕ ПУТИ (USER FLOWS)

====================

Нужно обязательно спроектировать и визуально отразить следующие пользовательские пути.

1. Новый пользователь

- открывает приложение;

- видит экран входа;

- вводит email;

- получает код;

- вводит код;

- попадает в приложение.

2. Пользователь читает бесплатный контент

- заходит в раздел “Посты”;

- видит ленту;

- открывает пост;

- читает;

- ставит реакцию;

- пишет комментарий;

- сохраняет в избранное.

3. Пользователь пытается открыть платный контент без подписки

- заходит в раздел “Школа здорового человека”;

- видит, что доступ ограничен;

- видит paywall;

- нажимает кнопку оплаты;

- уходит на сайт оплаты.

4. Пользователь оплачивает подписку

- переходит на внешний сайт;

- оплачивает подписку;

- возвращается в приложение;

- приложение автоматически проверяет статус оплаты;

- пользователь получает доступ к платному разделу.

5. Пользователь с активной подпиской

- открывает раздел “Школа здорового человека”;

- просматривает контент;

- открывает пост;

- смотрит видео;

- комментирует;

- добавляет материалы в избранное.

6. Пользователь получает push

- получает уведомление о новом посте;

- переходит по нажатию в приложение;

- сразу попадает в нужный контент.

7. Пользователь получает уведомление об окончании подписки

- видит напоминание;

- открывает приложение;

- переходит на экран подписки;

- оформляет продление.

8. Администратор публикует пост

- заходит в список постов;

- нажимает “создать пост”;

- пишет текст;

- добавляет эмодзи;

- добавляет фото и/или видео;

- выбирает раздел публикации;

- включает или отключает комментарии;

- публикует сразу или планирует на нужное время.

9. Администратор редактирует контент

- открывает черновик или опубликованный пост;

- вносит изменения;

- обновляет публикацию.

10. Модератор модерирует комментарии

- открывает комментарии;

- скрывает или удаляет нежелательный комментарий;

- сохраняет чистоту обсуждения.

6. ТРЕБОВАНИЯ К UX/UI

====================

Нужно сделать дизайн так, чтобы он был:

- интуитивным;

- очень понятным без обучения;

- удобным для чтения длинных постов;

- удобным для просмотра медиа;

- дружелюбным для взрослой аудитории;

- с хорошим размером шрифтов;

- с хорошим контрастом;

- без перегрузки декоративными элементами;

- с чистой навигацией;

- с понятным разделением бесплатного и платного контента;

- с мягкой, ненавязчивой монетизацией.

Нужно продумать:

- empty states;

- loading states;

- error states;

- locked states;

- subscribed / unsubscribed states;

- success states после оплаты;

- состояния черновика, запланированной публикации и опубликованного поста;

- состояния отсутствия комментариев, избранного, уведомлений.

7. НАВИГАЦИЯ

====================

Нужно предложить простую и логичную мобильную навигацию.

Скорее всего это должен быть нижний tab bar или аналогично простой паттерн.

Нужно предусмотреть основные точки входа:

- Посты

- Школа

- Избранное

- Профиль

Для администратора дополнительно:

- Посты / Управление постами

или другой аккуратный способ доступа к административным функциям без перегрузки главной навигации.
